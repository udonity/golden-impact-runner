# 完了前の検証

## 概要

検証なしに作業完了を主張するのは、効率ではなく不誠実さである。

**基本原則:** 常にエビデンスが先、主張は後。

**このルールの文言に違反することは、このルールの精神に違反することである。**

## 鉄則

```
新鮮な検証エビデンスなしに完了を主張してはならない
```

このメッセージ内で検証コマンドを実行していないなら、それが通ったとは主張できない。

## ゲート関数

```
ステータスの主張や満足の表明をする前に:

1. 特定: この主張を証明するコマンドは何か?
2. 実行: 完全なコマンドを実行する（新規に、完全に）
3. 読解: 出力全体を読み、終了コードを確認し、失敗数を数える
4. 確認: 出力が主張を裏付けているか?
   - いいえの場合: エビデンスとともに実際のステータスを述べる
   - はいの場合: エビデンスとともに主張を述べる
5. その後に初めて: 主張を行う

いずれかのステップを省略 = 検証ではなく嘘
```

## よくある失敗

| 主張 | 必要なもの | 不十分なもの |
|------|-----------|-------------|
| テスト通過 | テストコマンド出力: 失敗0件 | 以前の実行結果、「通るはず」 |
| リンタークリーン | リンター出力: エラー0件 | 部分的チェック、推測 |
| ビルド成功 | ビルドコマンド: exit 0 | リンター通過、ログが良さそう |
| バグ修正済み | 元の症状テスト: 通過 | コード変更した、修正されたはず |
| リグレッションテスト動作 | RED-GREENサイクル確認済み | テストが1回通っただけ |
| エージェント完了 | VCS差分で変更確認 | エージェントが「成功」と報告 |
| 要件充足 | 行ごとのチェックリスト | テスト通過 |

## 危険信号 - 停止せよ

- 「はず」「おそらく」「のようだ」を使っている
- 検証前に満足を表明している（「素晴らしい!」「完璧!」「完了!」など）
- 検証なしにコミット/プッシュ/PR しようとしている
- エージェントの成功報告を信用している
- 部分的な検証に頼っている
- 「今回だけ」と思っている
- 疲れて早く終わらせたい
- **検証を実行せずに成功を暗示するいかなる表現も**

## 合理化の防止

| 言い訳 | 現実 |
|--------|------|
| 「もう動くはず」 | 検証を実行せよ |
| 「確信がある」 | 確信 ≠ エビデンス |
| 「今回だけ」 | 例外なし |
| 「リンターは通った」 | リンター ≠ コンパイラ |
| 「エージェントが成功と言った」 | 独立して検証せよ |
| 「疲れた」 | 疲労 ≠ 言い訳 |
| 「部分的チェックで十分」 | 部分的では何も証明できない |
| 「別の言い方だからルール適用外」 | 文言より精神 |

## 重要パターン

**テスト:**
```
正 [テストコマンド実行] [結果: 34/34 通過] 「全テスト通過」
誤 「もう通るはず」 / 「正しく見える」
```

**リグレッションテスト (TDD RED-GREEN):**
```
正 作成 → 実行(通過) → 修正を戻す → 実行(必ず失敗) → 復元 → 実行(通過)
誤 「リグレッションテストを書きました」(RED-GREEN検証なし)
```

**ビルド:**
```
正 [ビルド実行] [結果: exit 0] 「ビルド通過」
誤 「リンターが通った」(リンターはコンパイルをチェックしない)
```

**要件:**
```
正 計画を再読 → チェックリスト作成 → 各項目を検証 → 差分または完了を報告
誤 「テスト通過、フェーズ完了」
```

**エージェント委任:**
```
正 エージェントが成功報告 → VCS差分を確認 → 変更を検証 → 実際の状態を報告
誤 エージェントの報告を信用する
```

## これが重要な理由

24件の失敗記録から:
- あなたの人間パートナーが「信用できない」と言った - 信頼の崩壊
- 未定義の関数が出荷された - クラッシュするはずだった
- 要件漏れのまま出荷された - 不完全な機能
- 偽の完了 → 方向転換 → やり直しで時間を浪費
- 違反: 「誠実さは核心的価値である。嘘をつけば、交代させられる。」

## 適用タイミング

**常に以下の前に:**
- 成功/完了の主張のあらゆるバリエーション
- 満足のあらゆる表明
- 作業状態に関するあらゆる肯定的な発言
- コミット、PR作成、タスク完了
- 次のタスクへの移行
- エージェントへの委任

**ルールの適用対象:**
- 正確なフレーズ
- 言い換えや同義語
- 成功の暗示
- 完了/正確性を示唆するあらゆるコミュニケーション

## 結論

**検証に近道はない。**

コマンドを実行する。出力を読む。その後に結果を主張する。

これは交渉の余地がない。
