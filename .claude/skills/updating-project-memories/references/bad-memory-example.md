# プロジェクト情報

## 一般的なメモ

プロジェクトは開発に TypeScript を使っている。いろんなディレクトリにさまざまなファイルがある。テストがあるファイルもあるし、ないファイルもある。コードは一般的なパターンに従っている。

## API のこと

API にはエンドポイントがある。データを返す。エラーが出ることもある。エラーハンドリングはコードのどこかでやっている。API は REST を使っていると思う。

## テスト

テストはたぶん Jest で書かれている。テストファイルにある。テストは通ったり通らなかったりする。テストはコード品質のために重要だ。

## アーキテクチャ

プロジェクトは良いアーキテクチャを持っている。ファイルは論理的に整理されている。フロントエンドとバックエンドのような異なるレイヤーがある。コンポーネントはモジュール化されている。

## 規約

ベストプラクティスに従っている。コードはクリーンで読みやすいべきだ。意味のある変数名を使う。繰り返しを避ける。関数を小さく保つ。

## データベース

データベースがある。データを保存する。テーブルにはカラムがある。データを取得するためにクエリを使う。スキーマはどこかに定義されている。

## デプロイ

アプリはどうにかしてデプロイされる。ビルドプロセスがある。設定のために環境変数が使われる。デプロイはだいたいうまく動く。

## なぜこれが悪いメモリか

❌ **曖昧:** 具体的なファイルパス・コード例・具体的なパターンがない  
❌ **実用的でない:** この情報では判断もコード記述もできない  
❌ **汎用的:** 「ベストプラクティス」「クリーンなコード」は自明であり、プロジェクト固有でない  
❌ **構造がない:** 曖昧な観察のランダムな羅列  
❌ **コンテキストなし:** 根拠・歴史・理由が欠如している  
❌ **役立たない表現:** 「テストがいくつか」「コードのどこかで」「たぶん」  
❌ **冗長:** ドキュメント化する必要のない自明な情報を繰り返す  
❌ **具体性なし:** すべての記述が汎用的で、どのプロジェクトにも当てはまる  

## 改善の原則

| 原則 | 悪い例 | 良い例 |
|------|--------|--------|
| 具体的なパスを示す | 「API にはエンドポイントがある」 | 「src/api/ の全エンドポイントは `{ status, data, error }` 形式を返す」 |
| 推測しない | 「テストはたぶん Jest」 | 「tests/ は Jest 使用。`npm test` で実行」 |
| 一時的な変更は記録しない | 「バグをいくつか修正した」 | そもそもメモリ化しない。パターンだけを記録 |
