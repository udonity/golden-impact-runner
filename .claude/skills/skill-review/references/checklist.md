# スキルレビューチェックリスト

迅速なスキルレビュー用の簡易検証チェックリスト。合格/不合格の監査に使用する。

---

## 構造

```
□ SKILL.md が存在する
□ ディレクトリ名がフロントマターの `name` と一致する
□ 不要なファイルがない（README.md、CHANGELOG.md など）
□ リファレンスは1階層のみ（チェーンなし）
□ フォワードスラッシュのみ（Windowsパスなし）
□ 本文中で参照されるスクリプトパスがディレクトリに存在する
□ 外部バイナリの依存関係が文書化されている
```

## フロントマター

```
□ name: 小文字とハイフンのみ [a-z0-9-]
□ name: 64文字以下
□ name: "anthropic" や "claude" を含まない
□ description: 空でない
□ description: 1024文字以下
□ description: 三人称
□ description: 何をするかを含む
□ description: いつトリガーするかを含む
```

## 説明文の品質

```
□ 具体的なアクション（"支援する" のような曖昧な表現でない）
□ トリガーフレーズを含む（"〜の場合に使用"）
□ 発見性のための類義語
□ 一人称/二人称なし（"I can"、"You can"）
```

## 本文内容

```
□ 合計500行未満
□ クイックスタートが上部にある
□ 詳細は references/ に配置（前面に出さない）
□ 長いリファレンス（100行超）には目次がある
□ リファレンスポインタが条件付き（「〜の場合 → ref.md」形式。無条件に参照していない）
□ references/ 総行数が SKILL.md 本文の3倍以内
□ Claudeが知っている自明な説明がない
□ 文章より例示を優先
□ 複数の選択肢がある場合はデフォルトを提供
```

## アンチパターン（検出されてはならない）

```
□ Windowsパスなし（scripts\file.py）
□ ネストされたリファレンスチェーンなし
□ 時間依存の記述なし（"2025年8月以前"）
□ 説明のないマジックナンバーなし
□ デフォルトなしの "XまたはYまたはZが使える" なし
□ 用語の不統一なし
□ スキルディレクトリ内にユーザー向けドキュメントなし
□ 無条件リファレンスポインタなし（必須セクションや手順内から直接 ref.md を参照していない）
□ リファレンス肥大化なし（references/ 総量が SKILL.md の3倍超でない）
```

## 任意要素

```
□ scripts/ - 実行可能コード（必要な場合）
□ references/ - 読み込まれるドキュメント（必要な場合）
□ assets/ - 出力テンプレート（必要な場合）
□ allowed-tools が適切にスコープされている（使用する場合）
```

---

## 簡易スコアリング

| カテゴリ | 重要度 | 合格/不合格 |
| -------- | ------ | ----------- |
| フロントマターが有効 | 必須 | |
| 説明文の品質 | 必須 | |
| 本文500行未満 | 必須 | |
| アンチパターンなし | 必須 | |
| 段階的開示 | 推奨 | |
| トークン効率 | 推奨 | |

**合格**: 全必須項目 + 推奨項目の大半を満たす
**要改善**: いずれかの必須項目が不合格
**不合格**: 複数の必須項目が不合格

## 説明文テンプレート

```yaml
description: >-
  [何をするか - 具体的なアクションと機能]。
  [トリガーフレーズ、コンテキスト、ファイル形式、ユーザーの意図]の場合に使用。
```

## 合格する説明文の例

```yaml
description: >-
  WCAG 2.1/2.2 AAに基づいてUIのアクセシビリティ問題をレビューする。
  「これはアクセシブル？」「アクセシビリティをチェック」
  またはコントラスト/a11yレビューのリクエスト時にトリガーされる。
```

## 不合格となる説明文の例

```yaml
# 曖昧すぎる
description: ドキュメントを支援する

# トリガーがない
description: PDFファイルを処理する

# 不適切な人称
description: データの分析をお手伝いします
```
