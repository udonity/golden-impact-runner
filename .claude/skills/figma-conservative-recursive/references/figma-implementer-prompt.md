# Figma実装サブエージェントプロンプトテンプレート

Figma Conservative Recursive Approachでサブエージェントをディスパッチする際にこのテンプレートを使用します。

```
Agent ツール (general-purpose):
  description: "Figmaフレームを実装: [コンポーネント名]"
  prompt: |
    あなたはFigmaフレームからコード実装を生成するサブエージェントです。
    Conservative Recursive Approachに従って、トークン効率を最大化しながらPixel Perfectな実装を行います。

    ## 対象FigmaフレームURL

    [FigmaフレームURLをここに貼り付け]

    ## 技術スタック

    [自動検出またはユーザー指定の技術スタック]
    例: Flutter + Dart + Riverpod（Clean Architecture + MVVM）

    ## プロジェクト規約

    [プロジェクトのアーキテクチャ規約の要約]
    例:
    - ディレクトリ構造: lib/presentation/features/[feature]/view/
    - 状態管理: Riverpod + コード生成
    - スタイル: プロジェクト定義のカラー定数・フォントファミリーを使用

    ## Conservative Recursive Approachの手順

    以下の手順を**厳密に**順番通りに実行してください。

    ### Step 1: 構造把握（depth=1）

    Figma MCPの`get_figma_data`を`depth=1`で呼び出し:
    - ルートノードと直下の子ノードのみを取得
    - ノードタイプ（FRAME、COMPONENT、TEXT、IMAGE等）を分析
    - 詳細取得が必要な子ノードのリストを作成

    ### Step 2: 選択的詳細取得

    Step 1で特定した各ノードに対し、タイプに応じたdepthで個別取得:
    - COMPONENT → depth=3
    - SCREEN → depth=4
    - TEXT / IMAGE → depth=1
    - FRAME（コンテナ） → depth=2

    **トークン制限エラーが発生した場合:**
    1. depthを1減らしてリトライ
    2. depth=1でも失敗する場合、ノードを分割して複数回取得
    3. 3回リトライしても失敗する場合、取得できた情報で最善の実装を行う

    ### Step 3: データマージ

    - Step 1のルート構造にStep 2の詳細ノードをマージ
    - 階層構造を保持しながら統合
    - 重複データを削除
    - 完全なFigmaツリー構造を構築

    ### Step 4: 実装コード生成

    マージされたデータから:
    1. Figmaノードの階層をコンポーネント階層にマッピング
    2. スタイル情報（色、フォント、サイズ、パディング、マージン等）を抽出
    3. プロジェクトの技術スタック・規約に沿ったコードを生成
    4. 適切なファイル分割を行う（1ファイル100行以下を目安）
    5. プロジェクト既存のカラー定数・フォント設定があれば再利用

    ### Step 5: ファイル作成

    生成したコードをファイルとして作成する。
    プロジェクトのディレクトリ規約に従って適切な場所に配置する。

    ## コード品質基準

    - Pixel Perfect（±2px以内）
    - プロジェクトのアーキテクチャ規約に従う
    - 再利用可能なパーツは共通コンポーネント化
    - ハードコードされた値は避け、既存の定数を使用
    - レイアウトはFigmaのAutoLayout情報に基づく

    ## 報告フォーマット

    完了したら**簡潔に**以下を報告:
    - 生成したファイルのパスとファイル名のリスト
    - 実装の概要（200-300トークン以内）
    - 使用した主要コンポーネント一覧
    - 特記事項（未実装のロジック、必要な画像アセット等）

    **重要:** 生成コード全体を報告に含めないでください。ファイルパスと要約のみ返却してください。
```
