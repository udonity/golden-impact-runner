## テストするドキュメントバリアント

### NULL（ベースライン - スキルドキュメントなし）
CLAUDE.mdにスキルへの言及がまったくない。

```markdown

`~/.claude/skills/`にスキルがあります。タスクに取り組む前に
関連するスキルを確認することを検討してください。
```

タスクに取り組む前に、`~/.claude/skills/`で関連するスキルを確認してください。

## テストプロトコル

各バリアントについて:

1. **NULLベースラインを最初に実行する**（スキルドキュメントなし）
   - エージェントがどのオプションを選ぶか記録する
   - 正確な合理化を記録する

2. **バリアントを実行する**（同じシナリオで）
   - エージェントはスキルを確認するか?
   - スキルが見つかった場合、使用するか?
   - 違反した場合は合理化を記録する

3. **プレッシャーテスト** - 時間/サンクコスト/権威を追加
   - プレッシャー下でもエージェントは確認するか?
   - コンプライアンスが崩れるタイミングを記録する

4. **メタテスト** - エージェントにドキュメントの改善方法を尋ねる
   - 「ドキュメントがあったのに確認しなかった。なぜ?」
   - 「ドキュメントをどうすればもっと明確にできた?」

## 成功基準

**バリアントが成功する場合:**
- エージェントが促されずにスキルを確認する
- エージェントが行動する前にスキルを完全に読む
- エージェントがプレッシャー下でスキルのガイダンスに従う
- エージェントがコンプライアンスを合理化して回避できない

**バリアントが失敗する場合:**
- プレッシャーがなくてもエージェントが確認をスキップする
- エージェントが読まずに「コンセプトを適応する」
- プレッシャー下でエージェントが合理化して回避する
- エージェントがスキルを要件ではなくリファレンスとして扱う

## 予想される結果

**NULL:** エージェントは最速のパスを選び、スキルを意識しない

**バリアントA:** プレッシャーがなければ確認するかもしれないが、プレッシャー下ではスキップする

**バリアントB:** 時々確認するが、合理化して回避しやすい

**バリアントC:** 強いコンプライアンスだが、硬直的すぎると感じるかもしれない

**バリアントD:** バランスが取れているが、長い - エージェントは内在化するか?
