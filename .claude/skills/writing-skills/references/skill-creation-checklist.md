# スキル作成チェックリスト（TDD適用版）

**重要: TodoWriteを使って、以下のチェックリスト項目ごとにtodoを作成すること。**

## REDフェーズ - 失敗するテストを書く

- [ ] プレッシャーシナリオを作成する（規律スキルは3つ以上のプレッシャーを組み合わせる）
- [ ] スキルなしでシナリオを実行する - ベースライン動作を原文のまま記録する
- [ ] 合理化/失敗のパターンを特定する

## GREENフェーズ - 最小限のスキルを書く

- [ ] 名前は英字、数字、ハイフンのみ（括弧/特殊文字不可）
- [ ] YAMLフロントマターはnameとdescriptionのみ（最大1024文字）
- [ ] descriptionは「Use when...」で始まり、具体的なトリガー/症状を含む
- [ ] descriptionは三人称で記述
- [ ] 検索用のキーワードを全体に散りばめる（エラー、症状、ツール）
- [ ] 基本原則を含む明確な概要
- [ ] REDで特定した具体的なベースライン失敗に対処する
- [ ] コードはインラインまたは別ファイルへのリンク
- [ ] 1つの優れた例（多言語でない）
- [ ] スキルありでシナリオを実行する - エージェントが準拠することを検証する

## REFACTORフェーズ - 抜け穴を塞ぐ

- [ ] テストからの新しい合理化を特定する
- [ ] 各抜け穴に明示的な対策を追加する（規律スキルの場合）
- [ ] すべてのテストイテレーションから合理化テーブルを構築する
- [ ] 危険信号リストを作成する
- [ ] 防弾になるまで再テストする

## 品質チェック

- [ ] 判断が非自明な場合のみ小さなフローチャート
- [ ] クイックリファレンステーブル
- [ ] よくある間違いセクション
- [ ] ナラティブなストーリーテリングなし
- [ ] サポートファイルはツールまたは大量のリファレンスの場合のみ

## デプロイ

- [ ] スキルをgitにコミットしてフォークにプッシュする（設定されている場合）
- [ ] PRでの貢献を検討する（広く有用な場合）
